# Layer 2 signal collector - human capital and talent flow

Collects dated, sourced talent and hiring signals: executive and senior technical hires, board
and advisory appointments, hires whose weight is the place the person came from, people leaving
to found companies, academic moves into industry, team lift-outs, and hiring surges counted from
companies' own job boards. Discovery only: nothing here prices, tiers or judges a stock.

Funding rounds, IPOs and fund positions are Layer 4; contracts and capacity are Layer 3. They
are stored but not kept as Layer 2 signals.

## Two layers of capture

1. **Wholesale.** Every filing and feed item that is reachable is stored with date, source and
   link before any filter: all 8-K / 6-K filings of the day are indexed (8-Ks carrying Item 5.02
   are opened with their EX-99 press release; 6-Ks and Form 3 of tracked companies are read), SEC
   full-text search covers the high-yield talent phrases for any filer, and every feed item is
   stored. The hiring snapshot stores every open role of every mapped board.
2. **Keyword combinations.** Each stored item is analysed sentence by sentence. A combination
   fires only when its parts sit in the same sentence (or sentence plus the next): an
   appointment verb + a senior title + a person name; an appointment + a pedigree organisation
   (Nvidia, Google, OpenAI, Intel, national laboratories ...) + prior role; board or advisory
   appointment; a departure to found or join a startup; an academic move into industry; several
   people moving together; newly created roles; hiring-surge wording with a count. Score =
   strongest combination + 1 per further distinct combination (max +3); kept when score >= the
   keep threshold in `keywords.json`. Boilerplate, bookkeeping titles (controller, treasurer,
   investor relations ...) and funding wording are skipped or flagged.

Hiring numbers are evidence that supports a talent signal or a sector; they never admit a company
on their own.

## What runs when

| Job | When (New York) | Started by | Writes |
|---|---|---|---|
| Hiring snapshot | Wednesday 10:30 PM | routine 00c pushes `triggers/hiring.txt` -> GitHub Action `Layer 2 - weekly hiring snapshot` | `data/hiring/...` |
| Daily collector | Every day 11:30 PM | routine 00a pushes `triggers/daily.txt` -> GitHub Action `Layer 2 - daily collector` | `data/daily/...` |
| Weekly packet | Thursday 12:00 AM (window Thursday-Wednesday) | routine 00b pushes `triggers/weekly.txt` -> GitHub Action `Layer 2 - weekly packet` | `data/weekly/<Wednesday>/` |
| Routines 01-04 | Thursday 1:00-4:00 AM | claude.ai routines | `research/layer 2/signal-discovery/<end-date>/` |

Each workflow also has a backup cron a few minutes after the kick-off and a manual
`workflow_dispatch` with an extra-arguments box. All workflows gate themselves (New York hour
window, already done today / this week), so a duplicate trigger does nothing. The hiring
snapshot has its own queue; the daily collector and the weekly packet share one.

Manual run from this folder:

```
python tools/build_feeds.py                          # after editing sectors.csv or the feed list
python layer2_daily.py                               # last 3 business days of SEC + full-text + feeds
python layer2_daily.py --only feeds --fresh          # feeds only, ignore the seen-items list
python layer2_hiring.py --limit 20                   # hiring snapshot, first 20 companies (testing)
python layer2_weekly.py --end-date 2026-10-14        # packet for the window ending that Wednesday
python tools/test_sources.py                         # re-test every source (--only feeds|sec|ats|datasets)
python tools/discover_ats.py                         # find job boards for companies (--limit, --recheck)
python tools/test_vocabulary.py --corpus <file>      # test the vocabulary against a corpus of reports
```

Requirements: Python 3.10+, `openpyxl`. No API keys. Network: sec.gov (descriptive User-Agent set
in `l2lib.py`), efts.sec.gov (full-text), the Greenhouse, Lever and Ashby public job-board JSON
endpoints, free hiring datasets (Indeed Hiring Lab), wire / trade-press / company-newsroom RSS,
news.google.com.

## How the vocabulary was built and tested

* Source: word and phrase counts of 1,351 published Layer 2 reports from the retired
  `hf-signal-framework` process (counted only; that process is not used otherwise). Files:
  `analysis/word-counts-top100-words.csv` (page counts in Deal signal sections vs non-signal
  sections, with lift), `analysis/word-counts-top100-phrases.csv` (same for phrases) and
  `analysis/word-counts-pedigree-orgs.csv` (organisations named as prior employers, e.g. Intel,
  Nvidia, Google, Microsoft).
* Test: `tools/test_vocabulary.py --corpus <file>` runs the combination rules over the old
  sections and writes `analysis/vocabulary-test.json`. Result: the rules reach the keep score on
  960 of 1,125 Deal signal sections (85%) and on 128 of 1,118 non-signal sections (11%).
* Measured precision per combination (signal sections that fire vs non-signal sections that fire):

test shows the vocabulary is selective, not that every kept item is a signal; routines 01-04 verify
each one.

## Known limits (stated, not hidden)

- Headlines are often in title case, so person-name detection (capitalised word pairs) is noisy
  on feed items; the person rules in `keywords.json` and the agents' verification cover it.
- Form 3 is also filed at IPO and when a person re-files; a Form 3 alone is not proof of a new
  hire (flag `form3-reaffiliation-check`).
- The ATS boards cover only companies that use Greenhouse, Lever or Ashby (154 mapped). There is
  no history before the first snapshot: the first run is a baseline, with blank change figures.
- A role that disappears from a board cannot be told apart as filled, cancelled or moved to
  another board. Replacement hiring looks like growth. Greenhouse lists give a last-updated date,
  not a posting date, so first-seen is used.
- Companies on Workday, Oracle, iCIMS, SuccessFactors, Taleo, SmartRecruiters or their own career
  sites, and public mega-caps (Nvidia, Google, Microsoft, Amazon, Intel, AMD, Broadcom ...), have
  no scripted job count; agents cover them in routine 03.
- LinkedIn, Indeed and Glassdoor are agent-only: manual lookups of public pages, never scraped in
  bulk and never logged into.
- SEC full-text search is an undocumented endpoint; it may change. A failure is logged in the
  daily health file and the sec module keeps working without it.
- Keyword combinations find what is phrased in recognisable words; the cross-sector routine is
  the backstop for the rest. Items the vocabulary did not recognise (including Item 5.02 filings)
  are kept in the packet for agents to read.
- The vocabulary comes from past reports, so it favours the phrasing of the sectors those reports
  covered.
